# HTML Report Studio 项目目标

## 同源的两种输出配置

自由笔记面向安全Markdown/HTML/PDF阅读；工程报告面向可复现的编号、受限语法与模板化输出。两者共用源、对象和解析，模式切换不改正文。模式身份贯穿导出、独立阅读及恢复；配色独立选择，帮助保留原视觉。自由笔记以题注或内容摘要辨认对象，工程报告继续严格编号。Word入口始终使用独立Bridge工程规则，基础组件与可选公式依赖不改变三项目分工，输入尽量兼容、输出按明确结构和模板约束，不追求任意双向等价。

更新于 2026-10-21。本项目持续提高程序对 Markdown 文档的确定性创建、识别、读取、定位、校验、受控修改和导出能力。`report.md` 与 `assets/` 是内容真源；AI 可协助生成和整理，确定性解析和校验不依赖 AI 反复理解正文。

自由笔记支持在同一份台账内按H1积累、聚焦和提取专题，配合连续空行留白与按需图片加载；可回编分册可独立恢复；也可直接从台账或专题建立临时工程稿，先预览/检查/编辑再交给已有Bridge/WPS编译，默认不回写；用户可查看差异后显式同步已冻结的源范围。1.0将这组能力作为当前稳定范围，继续维护真实反例与明确的接口/资源边界。既有多工程打开、保存和受控写入继续复用。

## 不变边界

- 现有稳定界面和操作习惯冻结，未经批准不重新设计。用户已确认预期效果的局部体验修复视为该范围授权，超出范围再确认；不替换 CodeMirror、不引入第二份正文模型。
- 复用现有对象验证、源范围、编号、引用、资源审计、revision 和保存机制，不因未封装 Agent API 就把既有能力说成未实现。
- 对象 ID 表示身份，显示编号按源顺序派生，样式由输出模板控制。三者分离，不把图号/表号写入 caption。
- 编辑器只理解文档结构，不解释工程专业参数含义，不运行文稿内任意代码。
- Word/WPS 编译和逆向识别是独立项目，可按版本消费同一语义 IR；不保证任意 Word 排版无损往返。

## 同源多端发布

桌面架构要求同一份核心源码和文档规则，同时构建当前浏览器形式及Windows桌面形式。宿主只适配窗口/系统能力与部署；核心版本/摘要、保存/草稿和Bridge/WPS配套由共用清单校验。桌面评估与正式交付状态见当前状态及长期路线，不因换宿主建立第二套编辑、解析或编号实现。

## 当前能力方向

已有基础以[当前状态](CURRENT_STATUS.md)为准，不把完成的 ID 加固、保存/导出或服务管理重复列为待开发。

- 最小块操作：HRS统一提供ID／UTF-16快照的plan/apply，Bridge委托；显式提交复用备份、原子保存和冲突拒绝。批量及附件写入仍按具体任务推进，不建立第二套块管理。
- 程序化 HTML：HRS 正式提供单份导出/恢复命令，桥接复用同一入口与原引擎；批量从真实需求推进，不模拟鼠标、不建立第二套生成器。
- HTML 兼容：安全排版标签经同一白名单显示，源码保留、附件归原审计；HTML 展示内容不另建工程对象或编号规则。
- 持续维护：按用户反馈修复明确问题，以少量准确测试保护具体契约；现行说明直接描述当前行为，版本变化由既有日志保存。
- 阅读呈现：标题语义与字号分开，完整表达H1—H6导航；深层标题不小于正文，局部呈现调整不改变源文、编号或对象身份。

普通段落通过结构块和源范围定位；标题保留层级及可选 ID；GFM 表保留原生语法和可选 ID；增强表、图/组图、公式继续按现行格式管理。完整逐段/列表项 AST 不作为当前必需结构，也不强制转成带 ID 的 JSON。

## 版本和交付纪律

发布版本独立存放，原始源码/便携 ZIP 保留。修改前保存 Git 基线并在独立分支工作；规则/开发工具维护不默认新发行。每轮检查四份目标/状态及相关规范帮助，仅在职责内事实变化时更新，不重复记录同一修复。发行时记录输入/输出哈希、提交/标签，检查源码/便携包/匹配补丁；当前包保留必要规范与背景，可脱离 Git 独立理解。具体流程见文档维护规则及已授权 Issue。

历史目标原文和当时决定的去向见[历史索引](HISTORY_INDEX.md)。历史计划不作为当前未完成任务。现行语法只有[源格式规范](../source_format_v1.md)一份。

编号只由文档策略控制，稳定ID和内容不因显隐变化。工程章节/图表固定编号，自由笔记可选择；块公式两模式均可选。原生Markdown表、Mermaid和已有对象共用编号，避免维护带号/不带号的平行类型。
