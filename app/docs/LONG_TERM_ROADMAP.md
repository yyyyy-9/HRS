# HTML Report Studio 长期路线

## 输出策略的持续方向

在同一源契约上维护自由/工程配置，而不分叉编辑器或存储格式。工程章号、摘要角色与模板代码排版已经具备；后续扩展必须给出可执行的白名单/降级规则。任意笔记方言、任意HTML到Word及完全无损双向不作为目标。原程序化块操作、批量编排和受限互通路线继续保留。

HTML Report Studio 是以 Markdown 为真源的离线结构化文档编辑、阅读和程序化操作工具。当前重点是在保护既有界面与使用习惯的前提下，提高同一份文稿的可解析性、定位可靠性、受控修改和输出复现能力。

自由笔记以同一总台账的专题查看和提取承接长期积累；可回编独立HTML是恢复交换载体，仅阅读分册用于分享；临时工程稿承接单篇预览与编译，不另建转换链。后续正式报告合稿继续在Bridge处理标题降级、资源/身份冲突及跨来源引用，WPS负责模板与原生Word结构。跨来源合稿不作为HRS V1发布的阻塞条件。

## 当前能力基础

稳定对象 ID、UTF-16 范围、源快照、编号/引用、资源哈希、revision 冲突、原子文件写、草稿、窗口租约、HTML 归档回编和 Agent A0 已存在。当前方向在此基础上维护跨语言一致性及可靠接口，复用既有对象系统、保存和服务机制；版本演进见更新日志。

## 近期能力路线

1. 保持跨语言契约、输入保真、旧 HTML 兼容和目标 Windows 验收。
2. 最小程序化块操作：HRS统一拥有plan/apply，独立桥接委托；继续按真实调用完善失败保护与批量隔离，不建立第二份持久文档模型或每段强制ID。
3. 程序化 HTML：HRS 正式 CLI 通过显式薄入口调用原引擎完成单份往返，桥接复用；批量状态、失败隔离和输入输出清单按具体 Issue 扩展。安全 HTML 沿同一预览/导出/回编链维护。
4. 根据真实调用补足通用 IR 语义及小范围模块职责，不以“完整 AST”或大规模服务重构为预设目标。

## 为独立 Word 双向转换保留的结构基础

同一语义契约描述类型、层级、原始内容、可选稳定 ID、编号策略、引用及资源。下游 Markdown→Word 编译器据此映射原生表格、标题、公式、样式和引用；Word→Markdown 识别器可重建相同语义。编辑器不实现这些转换。

自身生成 Word 可由下游保留机器身份/书签以提高往返可靠性；规范外部 Word 可以利用样式和原生对象；排版混乱的 Word 仍有歧义，须报告或保留无法表达的信息，不能宣称任意排版无损转换。普通 Markdown 继续保留源范围，不为 Word 需要强制全部 JSON 化或分配 ID。

## Windows桌面端：同一核心，两种宿主

方向是Windows 10/11 x64自带渲染内核，同时保留当前浏览器版和标准Python入口。一份核心源码更新后，由同一构建入口生成浏览器与桌面形式；当前已实现ZIP桌面宿主和离线核心更新，具体已测边界见当前状态，目标机/人工验收继续单列。

### 核心与宿主的边界

保持现有 `app/` 作为唯一核心，不搬出另一份桌面编辑器：HTML/CSS/JS、CodeMirror、Marked/SourceMap、预览、对象/编号/引用、保存/草稿、preflight、受控写入和Python服务全部复用。Bridge/WPS仍为独立配套组件。桌面壳只增加窗口、启动/关闭、系统菜单/文件交接、内置打印与部署更新的适配。

同一仓库的 `desktop/` 只维护宿主、受限preload、运行库锁和离线更新。浏览器入口继续启动同一Python服务；桌面入口用Electron窗口加载该服务本机地址。原编辑器/解析及Markdown/Word规则保持。前端不给文稿Node或任意本地文件权限，沿原安全HTML和资源审计；外链交给系统浏览器。参考[Electron进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)及[隔离建议](https://www.electronjs.org/docs/latest/tutorial/security)。

### 同步构建与版本

源代码只改一处，构建先冻结一份核心负载及App清单，再分发到浏览器便携、桌面和wheel/sdist/配套Full。桌面Core以普通文件位于 `resources/hrs/app/`，Python和Word组件继续位于配套的runtime/word_support，不把Python源码埋进只供JavaScript读取的app.asar。桌面壳自身可单独封装。

产品版本仍只读取 `app/release.json`；桌面package.json/安装器版本由该定义生成，不能再手填常量。发布清单同时记录core版本/提交/内容摘要、宿主协议及Electron/Python/Word组件指纹，拒绝界面与后端或组件混版。发布门禁逐字节比较同一版本不同分发中的核心文件；只有对应宿主验收通过才列入该次交付。

EXE负责启动程序或安装程序，随包仍可有运行库和资源目录。首期采用桌面完整ZIP，安装器随后接入；不强制单文件自解压。浏览器版继续保留，标准核心包仍可用于Python/conda，Electron只属于可选Windows桌面分发。

### 运行库成本与维护

Electron版本/官方下载及每文件指纹固定在运行库锁，Python和Word组件复用经核对的原发行组件；内核更新须重新运行宿主专项。内置浏览器是桌面体积的主要成本，具体压缩/展开大小绑定最终包，不把单次小样本内存或启动时间当普遍承诺。前期隔离评估仍保留在外层证据，不作为当前发行验收。

嵌入式Python须显式指定核心路径并核对实际health/清单，不能只换脚本参数却导入另一版本。父进程按真实Windows进程句柄绑定，异常退出只释放所属桌面租约，不能按PID猜测杀其他进程。

### 少量且明确的宿主适配

| 工作 | 复用与适配口径 |
| --- | --- |
| 启动/单实例 | 复用原动态本机端口、用户数据目录、状态及服务逻辑；桌面管理自己创建的服务，已有实例需握手及所有权检查 |
| 窗口关闭 | 窗口X、菜单退出与原草稿冲刷共用准备过程；操作或草稿失败保留窗口，不用keep-alive或强杀代替正常退出 |
| PDF/打印 | 桌面通过私有打印通道使用内置 `webContents.printToPDF` 渲染同一导出快照，原预检、资源/源摘要及输出提交保持；浏览器版保留现有方式 |
| 文件与剪贴板 | 延续现有Python受控读写/选择/图片暂存；核对对话框所属窗口、拖放、富剪贴板、中文IME和路径，不在壳里复制源文件保存链 |
| 外链/系统目录 | 复用同源显式API和成品凭证；拦截主窗口外部导航与新窗口，不让链接替换编辑器 |
| 数据和并行 | 工程继续位于用户目录，草稿/宿主缓存不写入安装资源；两种宿主并行编辑仍服从原revision/写锁，拒绝旧快照，不增加自动合并 |

窗口X与父进程异常退出有实际进程专项；系统关机仍须实机验收。现有CLI/A0/plan/apply继续独立使用；桌面桥接只暴露少量宿主能力，不提供任意文件写入或扩大Agent授权。

### 更新与验收安排

一次构建产出两端。日常编辑器修复可使用绑定基础与目标的离线核心包，Electron/Python/Word组件未变时无需重发整个运行时。内核、宿主协议或Word模型变化使用完整发行；固定内核也需要随产品维护，不能永久冻结。

更新清单须绑定基础与目标摘要/布局、宿主兼容范围和所需组件。停止写入后准备新版本、校验再切换，失败保留旧版本；用户文稿、草稿和偏好在安装资源之外。原R35覆盖包只适用于其指定R34 Full，不能直接当作桌面通用补丁。首期采用用户主动离线更新，不新增后台联网要求。

现有tools/test_catalog仍为测试选择唯一源：核心规则专项运行一次；跨宿主抽样验证编辑/保存/图表/公式/脚注/HTML和Word，桌面另外验证窗口X、实例复用、文件/剪贴板、外链、内置PDF/打印、离线安装/更新/回退及退出后的进程。一次核心或宿主变化只运行相应集合，避免复制整套测试。正式交付仍需Win10/Win11目标机验收。

受限宿主、关闭保护、内置PDF/原Word、ZIP双端构建及离线更新/回退进入当前实现。后续按Win10/Win11目标机反馈完善系统交互，并独立安排安装器、签名和可选更新分发；不把尚未取得的环境验收或安装器写成已完成。

[draw.io当前桌面源码](https://github.com/jgraph/drawio-desktop/blob/dev/package.json)同样以Electron包装编辑核心。本项目优先选择Electron，是基于现有前端/Python可直接复用及上述实际验证。WebView2共享运行时可做较小客户端，但仍需部署/维护运行时；随包固定版也能离线控制版本，[Microsoft说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)其二进制超过250MB。当前不同时维护第二种桌面引擎。

## 持续约束

对象身份、显示编号、样式相互独立；`report.md/assets` 始终为真源。编辑器不解释专业参数，不自动执行工程脚本。界面、技术栈、关键文档/Agent 契约变化按用户边界审查。参考思源、Quarto、JupyterLab、Tiptap 的机制，优先独立实现和自身模块复用，不照搬其存储或编辑内核。

技术债按真实问题小步处理，保留现有保存/服务能力，不把未封装接口误写成从未实现。PDF.js、LibreOffice和跨报告合并均不自动转为当前承诺。主题只影响呈现，原程序化与混合文稿路线持续保留。

## 当前公开维护顺序

浏览器核心与模板工具共用现有转换链维护。桌面宿主从同一核心构建并使用独立运行库；各发行目标单独验证系统集成。测试使用合成样本，发行内容由清单核对。
